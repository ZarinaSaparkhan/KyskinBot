# KyskinBot

Личный Telegram-бот для пары. Python, aiogram, SQLite.

## Возможности

- Просьбы о внимании и ответы текстом, голосовым или нативным кружочком.
- Конверты с посланиями, которые открываются в назначенное время.
- Подключение партнёра по личному приглашению, приветствие и сохранённый кружочек.
- Уведомление владелице о первом подключении партнёра.
- Случайные фотографии и видео котика с историей без частых повторов.
- Сохранение черновиков и состояния после перезапуска.

Подробное описание существующих сценариев: [docs/FEATURES.md](docs/FEATURES.md).

## Что находится в репозитории

| Файл / папка | Назначение |
| --- | --- |
| `bot.py` | Запуск, обработчики Telegram, меню и котики |
| `envelopes.py`, `envelope_store.py` | Конверты, приглашения, приветствие и их хранение |
| `attention.py`, `attention_store.py` | Просьбы о внимании, запись ответов и их хранение |
| `content_store.py` | Медиа и история отправок |
| `prepare_media.py`, `check_media.py` | Вспомогательные утилиты подготовки/проверки медиа |
| `tests/` | Автоматические проверки с вымышленными данными |
| `deploy/` | Установка на Ubuntu, systemd и резервное копирование |

Репозиторий содержит исходники. Токен, личная база пары, фотографии, видео, реальные приглашения и настройки SSH сюда не включены.

## Просмотр и локальная разработка

Код рассчитан на macOS / Linux. На сервере используется Python 3.12. На Mac также использовался Python 3.14.

Для разработки используйте отдельного тестового бота: одновременно запускать вторую копию с токеном работающего бота нельзя — Telegram выдаст конфликт polling.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В локальном `.env` заполните `BOT_TOKEN` и `ALLOWED_USER_IDS`. Настоящий `.env` не публикуйте и не вставляйте в issues, PR или логи.

Свои подготовленные JPG / PNG / MP4 / GIF положите в `media/`. Приватные файлы не отслеживаются Git. При первом запуске программа создаёт локальные базы; они также исключены из Git.

```sh
python bot.py
```

После запуска тестового экземпляра отправьте ему `/start` в Telegram. Для завершения процесса используйте `Ctrl+C`.

## Проверки без настоящих отправок в Telegram

Запускайте наборы отдельно: часть интеграционных проверок загружает временные копии модулей.

```sh
python -m unittest discover -s tests -p 'test_attention.py'
python -m unittest discover -s tests -p 'test_envelopes.py'
python -m unittest discover -s tests -p 'test_welcome.py'
python -m unittest discover -s tests -p 'test_cat_flow.py'
python -m unittest discover -s tests -p 'test_deploy.py'
python -m unittest discover -s tests -p 'test_prepare_media.py'
```

## Обновление работающего бота

Публикация или коммит в GitHub сами по себе не обновляют сервер. Действующая база пары остаётся на сервере. Не заменяйте её старой локальной копией при обновлении исходников.

Перед установкой новой версии нужны проверка изменений, резервная копия и контролируемый перезапуск единственного процесса. Инструкции: [deploy/README.md](deploy/README.md).
