# Сервер и обновления

Подготовленные скрипты рассчитаны на Ubuntu 24.04, Python 3.12 и systemd. Рабочая папка приложения — `/opt/kyskinbot`, служба — `kyskinbot.service`.

## Назначение файлов

- `install_server.sh` устанавливает зависимости, окружение и основной unit. Не запускает бот автоматически.
- `preflight.py` проверяет готовность уже подготовленного рабочего каталога с медиа и базами. Проверка для переноса существующего экземпляра, не инициализатор пустого проекта.
- `snapshot.py` создаёт консистентный снимок баз SQLite через backup API.
- `backup_server.sh`, `kyskinbot-backup.service`, `kyskinbot-backup.timer` — серверные резервные копии.
- `requirements.txt` — зависимости сервера; `requirements-resolved.txt` — зафиксированное окружение предыдущей установки.

## Изменение действующего экземпляра

1. Проверить изменения и выполнить соответствующие автономные тесты.
2. Сохранить старые исходники и свежую резервную копию рабочих баз.
3. Остановить единственную службу, установить проверенные исходники и запустить её.
4. Убедиться в начале polling и отсутствии ошибок.
5. При ошибке вернуть предыдущие исходники и восстановить работу службы.

Не перезаписывать `.env`, `history.sqlite3`, `data/envelopes.sqlite3` и `media/` при обычном обновлении кода. Их нет в репозитории. Не запускать Mac-копию с тем же токеном параллельно серверу.

## Резервные копии

Бэкап содержит личные данные, а серверный скрипт может копировать `.env`. Хранить вне Git: файлы `600`, каталоги `700`, ограниченный доступ. Отдельно нужна проверенная копия вне основного сервера.

Служба резервного копирования от root должна запускать защищённую root-owned копию скрипта `/usr/local/libexec/kyskinbot-backup.sh` и системный Python, не изменяемый пользователем бота файл в каталоге приложения. Каталог скрипта также должен принадлежать root.

Первичное размещение, перенос пользовательской базы и подключение к серверу требуют отдельных настроек. Пароли, SSH-ключи, реальные адреса доступа и токен в репозиторий не помещаются.
