# Кыскин бот

Личный Telegram-бот для пары: просьбы о внимании, конверты с отложенным открытием и фотографии и видео котика.

С 25 октября 2026 года бот работает на сервере Hoster.kz в `/opt/kyskinbot`, служба `kyskinbot.service` включена в автозагрузку. Mac можно выключать. Актуальные пользовательские базы находятся на сервере; копия проекта на Mac используется для подготовки изменений. Порядок разработки и обновлений описан в README репозитория и deploy/README.md.

## «Хочу к тебе 💛»

В нижнем меню есть четыре вида просьбы: **Кружочек 🎥**, **Услышать голос 🎙️**, **Созвониться 📞**, **Просто побыть рядом 💛**. Последний вариант предлагает созвон, во время которого каждый может заниматься своими делами. Перед передачей бот показывает просьбу и спрашивает подтверждение.

Получатель выбирает один из ваших ответов:

- **я туть 🥰**;
- **шушуть попозже котенок, я тоже хочу к тебе 🥺💛**;
- **давай запланируем время 🗓️💛**.

Для просьбы о голосовом или кружочке **я туть 🥰** открывает запись прямо в чате с ботом. Запись остаётся у отвечающего до нажатия **Отправить 💌**; после подтверждения партнёру приходят ответ и нативное голосовое или кружочек. Перед отправкой доступны **Перезаписать 🎙️** / **Переснять 🎥**, возврат к предыдущей записи, **Отправить только ответ** и **Не отправлять запись 🌿**. Можно прислать новую запись того же типа без отдельного нажатия — она заменит черновик. Старые кнопки отправки после замены недействительны. Формат не преобразуется, бот повторно использует Telegram `file_id` ([sendVoice](https://core.telegram.org/bots/api#sendvoice), [sendVideoNote](https://core.telegram.org/bots/api#sendvideonote)).

**шушуть попозже…** и **давай запланируем время…** приходят сразу. После «попозже» можно вернуться к просьбе и выбрать «я туть», затем записать ответ. После отправки только текста к просьбе можно добавить одну запись. Черновик сохраняется при переходе в меню или конверты; **Продолжить ответ 💌** возвращает к нему. **Не отправлять запись 🌿** или `/cancel` при активной записи удаляет её черновик, сохраняя просьбу. Команда `/cancel` без активной записи сохраняет прежний смысл отмены черновика конверта.

При готовности или предложении запланировать время кнопка **В наш чат 💛** открывает личный чат, если известно имя пользователя; иначе бот предлагает открыть профиль. Созвон и время для него вы согласовываете в вашем личном чате. Доставка текстового ответа и записи учитывается отдельно: если текст уже доставлен, повтор после ошибки отправляет только запись.

**В меню 🐾** сохраняет уже отправленную просьбу; **Мы уже пообщались 💛** завершает её. У каждого участника может быть одна активная исходящая просьба, при этом оба могут попросить внимания независимо друг от друга. Автоматических напоминаний нет. При неподтверждённой доставке доступен ручной повтор. При сетевом обрыве после принятия сообщения Telegram такой повтор может доставить сообщение ещё раз.

Пока второй участник не подключён по приглашению, владелице доступна **проба**: просьба и ответы видны только ей, можно посмотреть оба экрана. Пробная просьба не становится настоящей после подключения партнёра. Просьбы, ответы и подтверждаемые черновики хранятся в той же базе `data/envelopes.sqlite3` и сохраняются после перезапуска.

Проверки без сети: `python -m unittest discover -s tests -p 'test_attention.py'`.

## Конверты «Откроешь потом 💌»

После `/start` есть отдельная нижняя кнопка **Откроешь потом 💌**. Можно выбрать текст, фото, голосовое или кружочек. Голосовое и кружочек записываются обычными средствами Telegram прямо в чате бота; выбирать или загружать файл с компьютера не нужно. Бот повторно использует Telegram `file_id`, сохраняя формат записи.

Далее можно добавить подпись, выбрать надпись на закрытом конверте и время открытия. При первом создании бот уточняет часовой пояс: Астана или Калгари. Перед запечатыванием показывает послание отправителю и время в обоих городах. Неоднозначное или несуществующее местное время при переводе часов отклоняется.

После отправки фото или записи бот предлагает **Подходит, дальше 💌**, замену вложения и **Отменить конверт 🌿**. Кружочек можно переснять, голосовое перезаписать, фото заменить на любом этапе до запечатывания. Можно просто отправить новую запись того же типа — она заменит предыдущую, а бот попросит её подтвердить. Подпись, надпись и выбранное время сохраняются. Если передумала переснимать, кнопка **Оставить предыдущий вариант** возвращает прежнюю запись. Старые кнопки после замены больше не запечатывают конверт.

**Отменить конверт 🌿** доступно на каждом шаге; команда `/cancel` отменяет текущий черновик, в том числе отложенный через меню. **В меню 🐾** сохраняет черновик, чтобы продолжить позже. Запечатанный конверт можно отменить через **От тебя 💌**, пока получатель его не открыл. Отменённый конверт не открывается и не вызывает уведомлений; отправитель сохраняет отметку об отмене в своём списке. Сообщения с первоначальными записями в чате Telegram автоматически не удаляются.

Получатель видит только надпись и дату до срока открытия. Проверка времени выполняется на стороне бота при каждом нажатии, а содержимое отправляется только после разрешённого открытия. Записи остаются голосовыми и кружочками. К кружочку подпись приходит отдельным сообщением: у Telegram video note нет поля caption.

Черновики, настройки, ссылки на медиа и запечатанные конверты хранятся в `data/envelopes.sqlite3`. Перезапуск программы их не удаляет. База не содержит скачанных копий аудио и видео: сами записи остаются в Telegram. Не удаляй эту базу, если хочешь сохранить послания.

### Подготовка сюрприза без предварительного входа партнёра

Когда в `.env` указан только ID владелицы, конверты можно подготовить до подключения второго участника. В меню конвертов доступна кнопка **Приглашение для сюрприза 🎁**. Она создаёт личную одноразовую ссылку на этот бот. Новая ссылка заменяет предыдущую ещё не использованную.

Отправь приглашение своей половинке, когда захочешь вручить готовый сюрприз. При первом запуске по этой ссылке Telegram ID подключается к вашей паре автоматически, а заранее приготовленные конверты закрепляются за получателем. Запрашивать его ID или просить заранее запускать бота не требуется. Приглашение даёт доступ к личному боту, поэтому предназначено одному получателю. После подключения другого человека по использованной ссылке подключить нельзя.

При открытии приглашения бот показывает согласованное личное приветствие от владелицы: «Хочу, чтобы ты улыбнулся, когда увидишь, что я для тебя приготовила 🤍» с завершением «Обнимаю тебя, котёнок 🫂». Текст хранится в `GIFT_GREETING` в `envelopes.py`; под ним доступно основное меню.

Перед вручением можно добавить нативный кружочек: **Откроешь потом 💌 → Приветствие для сюрприза 🎁 → Добавить кружочек 🎥**. Запись сначала показывается только владелице, сохраняется после **Сохранить для приветствия 💌**. Доступны пересъёмка, прежний вариант, отмена, пауза через меню и продолжение после перезапуска. Сохранённый кружочек отправляется получателю сразу после приветственного текста при первом входе по действующему личному приглашению. Черновик и его старые кнопки не публикуют неподтверждённый вариант. После подключения приветствие доступно для просмотра, дальнейшие записи отправляются конвертами.

Доставка приветственного текста и кружочка учитывается отдельно в `gift_welcome_delivery`: известная частичная ошибка повторяет только недоставленную часть. Снимок приветствия фиксируется после принятия приглашения, до этого отправок получателю нет. Повторное открытие ссылки и обычный `/start` не повторяют уже доставленные части. При неоднозначном сетевом обрыве Telegram не предоставляет гарантию exactly-once; известные успешные отправки не повторяются.

После первого принятия личного приглашения владелице приходит **«Он уже туть 🤍 Твоя половинка подключилась»** (`GIFT_JOIN_NOTICE`). Статус успешной отправки сохраняется в базе; повторные входы и перезапуск не повторяют уведомление. Доставка и повторы уведомления независимы от приветствия партнёру и настроек конвертов. Временная ошибка повторяется фоновым работником, блокировка бота владелицей прекращает повторы. Обновление старой базы не уведомляет о прошлых подключениях.

До первого запуска получателя сообщения ему не отправляются. Уведомления об открытии изначально выключены; каждый участник может включить или отключить свои уведомления в меню конвертов. После включения бот проверяет готовые конверты каждые 15 секунд. При выключенных уведомлениях конверты доступны через раздел **Для тебя**. Программа работает на постоянном сервере.

Проверка без сети и без настоящих сообщений:

```sh
python tests/test_envelopes.py
```

## Как он работает

1. `/start` показывает нижние кнопки **Хочу к тебе 💛**, **Откроешь потом 💌** и **Нужен котик**.
2. **Нужен котик** сразу отправляет случайное фото, видео или GIF с подписью «Воть».
3. Под медиа две кнопки: **Ещё 🐾** отправляет следующее медиа с подписью «Воть ещё»; **Усё 💛** завершает просмотр.
4. После **Усё 💛** приходит последнее фото с одним из четырёх пожеланий: «Шпасибо 🙇🏻‍♀️ а это вам на удачу 🍀», «…на счастье 🍀», «…на благополучие 🍀», «…на успех 🍀». Под ним нет кнопок продолжения; нижнее меню остаётся.

Выбор настроений и подборки фактов, цитат и шуток отключены. Сценарий котика работает без этих текстовых библиотек.

Использованные кнопки под прежними сообщениями убираются. Повторные быстрые нажатия и старые кнопки не отправляют лишние фото.

## Управление работающим ботом

Проверка серверной службы с настроенного Mac:

```sh
ssh -F '/Users/kitsune/Library/Application Support/KyskinBot/server-access/ssh_config' kyskinbot-hoster 'systemctl is-active kyskinbot.service'
```

Одновременно должен работать один polling-процесс. Локальный запуск с тем же токеном допускается после контролируемого возврата актуальных серверных данных и остановки службы — процедура описана в `deploy/README.md`. Старые базы на Mac после переноса не обновляются автоматически.

После обновления отправь боту `/start`, чтобы заменить прежнюю нижнюю клавиатуру.

Перенос, резервные копии и восстановление описаны в [deploy/README.md](deploy/README.md). Перенос завершён, автозапуск после настоящей перезагрузки проверен.

## Настройки в `.env`

```dotenv
BOT_TOKEN=токен_от_BotFather
ALLOWED_USER_IDS=числовой_ID_владелицы
```

Существующий токен сохраняется. Не публикуй `.env` и не отправляй токен в переписку. `/myid` показывает собственный Telegram ID для настройки доступа. Для сюрприза укажи только свой ID, а партнёра подключи приглашением, когда подарок готов. Допускается и прежняя настройка с двумя ID через запятую. Фотографии доступны только участникам личного бота и только в личном чате. `CONTACT_USERNAME` для сценария котика больше не требуется; переход в общий личный чат в разделе внимания использует данные подключённой пары.

## Фото и видео

Общая коллекция лежит в `media/`, включая вложенные папки. Поддерживаются `.jpg`, `.jpeg`, `.png`, `.mp4` и `.gif`. Подготовленные видео отправляются как видео с воспроизведением внутри Telegram; GIF — как анимация. Делить коллекцию по настроениям не нужно. Скрытые папки с ещё не готовыми файлами бот пропускает.

Работающая коллекция находится в `/opt/kyskinbot/media` на сервере. Изменение папки `media/` на Mac само по себе не меняет сервер. Подготовленные добавления/удаления переносятся как отдельное обновление коллекции. На сервере новые и удалённые файлы учитываются при следующем запросе; перезапуск для этого не нужен. После «Усё» всегда выбирается фотография.

### Добавление альбома с iPhone

1. В «Фото» на Mac открой нужный альбом и выдели объекты.
2. Выбери **Файл → Экспортировать → Экспортировать оригинал без изменений** и сохрани в папку `incoming/` внутри проекта. Это сохраняет настоящие видеозаписи. Live Photo может дать два файла: фото и короткое видео.
3. Проверь объём перед подготовкой:

```sh
python prepare_media.py incoming --inspect
```

4. Если свободного места достаточно для подготовленных копий, запусти:

```sh
python prepare_media.py incoming
```

Для большой коллекции можно подготовить более компактные копии видео:

```sh
python prepare_media.py incoming --video-edge 720 --video-crf 26
```

Обработчик сначала добавляет фотографии, затем видео. Перед чтением облачного оригинала он проверяет запас места с учётом его загрузки и временных файлов. При нехватке места останавливается, оставляя минимум около 2 ГиБ по проверке перед очередным файлом; изменения свободного места другими программами не контролируются. Повторный запуск продолжает работу по журналу. Текущий результат и список отложенных файлов записываются в `media/.import_report.json`. WebP также преобразуется в JPEG. Файлы `.aae` содержат сведения о правках и не добавляются в коллекцию как фотографии.

Программа создаёт отдельные JPEG (до 2048 пикселей) и MP4 (H.264/AAC, до 1080p, до 48 МБ), уменьшает слишком большие видео и переводит HDR в SDR. Длительность проверяется; длинные видео, которые не удаётся вместить в лимит, попадут в отчёт об ошибках. Оригиналы сохраняются. VLC не нужен: FFmpeg установлен вместе с зависимостями проекта.

Повторный запуск пропускает уже обработанные оригиналы. Удалённые вручную готовые файлы с записью в журнале импорта не восстанавливаются. Проверяются точные совпадения файлов, а не визуальное сходство разных экспортов одной фотографии. Ошибки записываются в `incoming/import_errors.json`; остальные файлы продолжают обрабатываться. Подготовка большой коллекции занимает время и место на диске. Загружать всю медиатеку iCloud для этого не нужно.

По твоему решению короткие видео `IMG_2711.mov` и `IMG_2850.mov` пропущены. Их фотографии уже есть в коллекции. Пропуски записаны в `media/.import_skipped.json`: файл с прежним размером и временем изменения не загружается из iCloud и не обрабатывается повторно. Новый экспорт с изменёнными размером или временем снова проверяется. Чтобы вернуть прежний файл в обработку, удали его запись из списка пропусков. Оригиналы остаются в `incoming/`.

## Повторы и история

`history.sqlite3` хранит отправленный контент отдельно для каждого человека. Фото, видео и анимации проходят отдельные круги: внутри своего круга файл не повторяется. После исчерпания соответствующей коллекции начинается новый круг; бот также избегает последних трёх вариантов на границе кругов, если вариантов достаточно. Пожелания проходят свой отдельный круг из четырёх вариантов. Тип медиа выбирается случайно с учётом количества файлов; финальное фото тоже учитывается в круге фотографий. История прежней версии сохранена и учитывается при выборе котика.

История и активные кнопки сохраняются после перезапуска. Медиа и пожелания записываются в историю после успешной отправки. Не удаляй `history.sqlite3`, если хочешь сохранить историю показов. Обновление кода не очищает старую историю.

## Проверки

При необходимости проверить сохранённые подборки прежней версии:

```sh
python check_content.py
```

Проверить их исходную комплектность из 1000 записей каждого типа:

```sh
python check_content.py --expect 1000
```

Проверки сценариев работают без сети, с тестовыми ID и без настоящих сообщений в Telegram:

```sh
python tests/test_cat_flow.py
python tests/test_attention.py
python tests/test_envelopes.py
python tests/test_prepare_media.py
```

Прежние личные сообщения и старый файл цитат также сохранены в проекте.
